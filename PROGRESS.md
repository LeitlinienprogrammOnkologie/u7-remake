## How to run

Open the **`godot/`** project in Godot 4.7 (C# / .NET 8). Data root is the repo (`u7/STATIC/U7MAP` must exist). `u7/`, `exult/` and `assets/` are not tracked; [README.md](README.md) explains how to provide them. A new game starts from `STATIC/INITGAME.DAT` (not `u7/GAMEDAT`, which holds a game already past the opening): Trinsic **1079, 2214**, hour **6:00**, with the opening scene.

| Key / input | Action |
|---|---|
| WASD / arrows | Walk while held (fast; Shift: medium) |
| Right button | Exult's: hold to walk toward the cursor (speed by distance), let go to stop; a double right-click walks a path there; a right-click on a gump closes it |
| Left button | Hold on open ground to walk toward the cursor, a quick click there walks a path (the user's pick, besides the right button); drag items; a click on a thing names it (half a second later, unless it is a double-click) |
| Shift+click | Teleport avatar to tile |
| Double-click / E | Use object or run NPC usecode `0x400+id` |
| I | Avatar inventory |
| C | Toggle combat (walk to nearest foe and auto-strike) |
| F4 | Toggle avatar invincibility (hits still flash / bark) |
| [ ] | Skip −1 / +1 hour |
| Home | Return to Trinsic start |
| PgUp / PgDn | Debug: avatar lift +1 / -1 in place (re-checks eggs at the new lift) |
| F5 / F9 | Save / load the quick slot (`saves/quick/`) |
| F6 | Debug: lethal damage to the avatar with global flag 0x57 set, so usecode 0x60E puts the party in the Fellowship shelter in Paws (836,1733); Shift+F6 leaves the flag alone, in which case the original restarts the game |
| M | Toggle music |
| F2 | Usecode / gump debug |
| F3 | Combat arena (heal, spawn 3 rats, combat on) |
| Mouse wheel | Zoom 1–8× |

### Agent console (automated play-testing)

With the environment variable `U7_AGENT=<dir>` set, `Game/U7Game.Agent.cs` reads one command per line from `<dir>/cmd.txt` and appends results to `<dir>/out.txt`, each ending in `DONE <n>`. Game time is frozen between commands, music is off, and conversation text, barks, fades (`FADE in|out, n steps (ms)`) and cursor flashes (`FLASH too heavy`) are logged; a command ends once a fade or flash it started is over. Commands: `look [r]` (actors with their alignment and facing, things not okay to take marked `owned`), `find <text>` (`find owned`: the things not okay to take, in containers too), `npc <num|name>` (also its attack mode, the player's or usecode's, and oppressor), `call <fun> [id|npc:n] [event]` (a test shortcut: runs a usecode function, hex, on an object, by default the avatar with event 1; the spells' functions this way skip the book), `state`, `inv [npc|id]`, `flags` (the global flags changed since the start) or `flags <hex> <0|1>` (sets one, a test shortcut), `setflag <npc|id> <flag> [0|1]` (an object flag by number or `ObjFlag` name, e.g. `setflag npc:1 invisible`), `timer [n] [hours-ago]`, `stubs`, `tile <x> <y> [z]`, `eggs [type] [radius]` (the eggs near the avatar, of one type by number or name: criteria, area, chance, data 1 and 2, hatched; default 40 tiles), `walk <x> <y>`, `walkto <id|npc:num>`, `steer <dir|0-7> <sec> [ms]`, `tp <x> <y> [z]`, `talk`/`use <id|npc>` (a double-click: the avatar opens its paperdoll, an NPC runs its usecode, an enemy is attacked in combat mode; refused while usecode runs, as is `save`), `drop <id> <x> <y> [z]` (a drag onto a tile, the whole stack), `take <id>` (a drag into the avatar's gump, a theft if the thing isn't okay to take), `sail <x> <y>` (in barge mode: the barge's centre heads there, as with the button held, until it stops), `put <id> <container-id>` (a drag into a container, also off a ready spot; a theft as `take`), `attack <id>` (a double-click in combat mode: anyone, not only enemies), `name <id>|gump` (a left click on a thing or the topmost gump, Exult `show_items`: the name shown over it), `rmouse <x> <y> <sec>|double` (the right button held over a tile, or double-clicked), `rclose` (a right-click on the topmost gump), `drag <id>` (the start of a mouse drag of a thing in the world, with Exult's checks and their flash, then put back), `cursor <x> <y>` (the cursor with the mouse over a tile, and the walking speed it means; headless games have no mouse), `endgame [won|lost]` (a test shortcut: usecode's `run_endgame`; its parts are logged as `ENDGAME ...` lines, `cont` skips as a key does, and the game stays when it is over), `book [page]` (the open spellbook's page, spells and bookmark; turns to a page) and `cast <spell>` (a double-click on a spell in it), `close`, `cont [n|all]` (also closes a picture or the Wizard Eye, as Esc: the WAIT line names the sprite, the map's mark, where a view elsewhere looks and the eye's time left), `eye <dir> [tiles]` (the Wizard Eye moved as the held right button does, a tile a step, 0 north clockwise), `choose <answer|#n>`, `num <n>`, `click <id>` or `click <x> <y> [z]` (a tile, for `click_on_item`), `wait <sec>`, `hour <h> [m]` (also prints `light`), `sprite <n> [frame]` (a SPRITES.VGA animation over the avatar, from a frame), `damage <n> [type]` (damage to the avatar through the normal path: tells whether it flashed red or showed the outline), `die [restart]` (F6: a lethal hit on the avatar; flag 0x57 is set so the party wakes in Paws, unless `restart`), `weather [<n> [min] | lightning | eggs [radius]]` (the weather, the clock's overcast and fog counts, the flashes so far and each weather effect; sets the weather as usecode does, 15 minutes unless given; adds usecode's lightning; lists the weather eggs near the avatar with their weather and minutes), `light` (the palette blend, dungeon, final palette, the light spell's minutes left and strength, Exult's light level and class, the avatar's carried light, and the top lights: shape, frame, brightness, tile, kind, radius), `save`/`load <slot>`, `shot <name>` (windowed only), `quit` (how a windowed run ends: only headless games may be stopped from outside). Object ids come from `look`/`find` output. Helpers: `pwsh scripts/agent/restart.ps1 [-Load <slot>] [-Io <dir>]` starts it headless (I/O in `agent_io/`, or its own folder with `-Io`, so several games can run side by side, each restarting only itself), `python scripts/agent/agent.py "<cmd>" ...` sends commands and prints the results (to `$U7_AGENT` when set). `walkto` goes to a free tile beside the target and `walk` says where it stopped short; `find` also searches what the party carries; `npc`/`look` give an actor's hit points; `choose` and `num` refuse while nothing asks for them (text waiting for a click needs `cont` first). The Trinsic murder chapter (opening, stables, Finnigan, Spark, the chest, Gilberto, Gargan, the report and map quiz, Johnson's gate) and Britain's first visit were played through this way.

### Temporary objects (current)

- Exult `Game_map::cache_out`: whenever the avatar enters a new superchunk, spawned monsters, their corpses and items flagged temporary outside the surrounding 3×3 superchunks are deleted (`GameMap.CacheOut`). Auto-reset monster eggs therefore respawn on a later visit, as in Exult.

### Shape data (current)

- `Data/ShapeFrame` ports Exult's `Shape_frame`: a frame as palette indices, its RLE unpacked into scans (runs of opaque pixels placed from the hotspot) over one packed index array. Raw 8×8 terrain frames (shapes 0-149, length/64 frames) are eight scans at -8,-8 with extents 8, 8, -1, -1, where Exult's `copy8` paints them. `Reflect` is Exult's: transposed into a square of 255s and scanned again, so index 255 drops out (SHAPES.VGA has no opaque 255). `Covers` is `has_point`: a pixel of slack at each end of a scan; flats get Exult's extents test, which misses their last row and column.
- `VgaShapeFile.DecodeFrame(shape, frame, wrap)` is Exult's `Shape::read`. Without wrapping (SHAPES.VGA, SPRITES.VGA) a frame past the last is none, bit 5 asks for the reflection, and terrain ignores the bits above 31. GUMPS, FONTS and FACES keep wrapping frame numbers and decode through it unchanged (checked frame by frame against the old decoder).
- `Data/U7Palette`: PALETTES.FLX entries as stored (`Raw6`, 6-bit), converted with Exult's `Get_color8` (v·255/63, as the extracted PNGs were; before, v·4) and `FindColor` (Exult `find_color`, below the rotating colours by default). Gumps, fonts, faces and sprites got up to 3 levels brighter with it.
- `Data/XformTables`: XFORM.TBL's 17 tables, stored in reverse as Exult does: table i serves index 0xEE + i, and file entry 0, the invisible actors' table, is the last. Without the file they are built from Exult's blends (`create_trans_table`), which disagree with the file on 139-252 of each table's 256 entries.
- Verified with temporary startup code: all 14171 SHAPES.VGA frames decoded with the day palette equal the extracted PNGs pixel for pixel; their extents equal `ShapeCatalog`'s (except terrain, which the CSV gives as 0, 0, 7, 7); every reflection's extents equal `GetFrame(frame | 32)`'s and its pixels are the transposed frame's; 183 shapes use indices 0xE0-0xFE, the same shapes as the cycle scan (its other 58 entries are animated shapes without them). Decoding every frame takes about 40 ms, reflecting them all 130 ms more.
- `Rendering/ShapeCache` reads SHAPES.VGA at runtime: `GetFrame8` keeps 64 slots a shape like Exult's `Shape` (frames 32-63 reflected from the decoded frame when first asked for), `GetSprite8` the same for SPRITES.VGA, `Xforms` the tables. `Get` builds the RGBA textures the gumps draw (container and paperdoll items, the drag ghost) from `GetFrame8` in the day palette, and the chunk flats copy raw terrain frames as Exult's `render_flats` does. The extracted shape PNGs are no longer read.
- Verified with before/after windowed shots: Trinsic (quest4), Lord British's castle (britain1), a campfire, a container with the paperdoll, an item being dragged: pixel-identical. Picks gain the pixel of slack (points of a shape's rectangle that pick it: Lord British 419 to 477, a campfire 237 to 300, a dagger in a backpack 39 to 63). The first full world frame after a load takes 31-44 ms instead of 110-125 ms; `ShapeCache` takes 3-8 ms to set up (reading SHAPES.VGA).

### Rendering (current)

- `WorldView` paints the world as Exult does, into an 8-bit buffer of palette indices (`Rendering/IndexBuffer8`, Exult's `Image_buffer8`) the size of the view plus a pixel round it, with a parallel glow plane: six bits of glow (magic pixels, see "Lighting (current)") and two marks for the world shader, roof (building-class objects from lift 3, which window light skips) and pane (the see-through pixels of glass), plus a pane plane noting each pane pixel's window and table. Each frame: index 0 everywhere, the chunks' flats, the flat RLE objects, the other objects in dependency order, the dungeon blackness (index 0, Exult `paint_blackness`), then the sprites. Painters clip per scan.
- Flats are Exult's `Chunk_terrain::render_flats`: a 128×128 picture of indices per terrain (raw 8×8 terrain frames only), kept for the 256 most recently used terrains.
- The buffer goes up as one RG8 texture (red the index, green the glow) drawn once, through the world shader, which looks the index up in `Rendering/WorldPalette`'s two rows and lights it (see "Lighting (current)"). Usecode's fades are drawn over everything by `Rendering/ScreenFx` (see "Lighting (current)").
- Colour cycling is Exult's `Game_window::rotatecolours`: every 100 ms of real time (the user's pick between Exult's 100 and 200) each of the ranges 0xFC-0xFE, 0xF8-0xFB, 0xF4-0xF7, 0xF0-0xF3, 0xE8-0xEF and 0xE0-0xE7 moves round by one, the last colour into the first slot (`Image_window8::rotate_colors`), and the palette texture is updated only then. It keeps going in gump mode, conversations and books, as in Exult, but holds while usecode waits for a target click (`click_on_item`), as Exult's other `Get_click` waits do. Sprites' translucent pixels have already been turned into other indices by the tables, so only opaque colours cycle, as in Exult.
- Verified with pairs of windowed shots about 330 ms apart, object animation held still: at the sea off Trinsic (its sparkles), a campfire (3824 screen pixels changed) and elsewhere, every changed pixel lies on a buffer index in 0xE0-0xFE.
- Translucency is Exult's `Shape_manager::paint_shape`: the 52 shapes with the TFA translucency flag (windows, stained glass, glass walls, lamp posts, fire and energy fields, ghosts, the wisp, ...) and every actor are painted with `paint_rle_translucent`, so their colours 0xEE-0xFE turn what is under them through XFORM.TBL's tables.
- Actors are painted as Exult's `Actor::paint`: not at all while `dont_move` (BG's `bg_dont_render`); an invisible actor only if it is the avatar or in the party, then through the invisible table (`paint_invisible`, XFORM.TBL's entry 0), a see-through silhouette; otherwise translucent. Then one outline (`paint_rle_outline`): red for a hit in the last 200 ms, else light blue charmed, purple paralysed, light grey protected, yellow cursed or green poisoned, the first that applies. `WorldPalette` finds those colours as Exult does (`special_pixels`, `find_color`).
- In gumps (still RGBA textures), TFA-translucent shapes such as reagents show their translucent colours as blend colour and alpha (Exult turns the gump's pixels under them through the tables).
- Verified with windowed shots from `britain1` against the previous renderer: the stained glass and windows of Lord British's castle and of the town, a lamp post (889), a fire field and a ghost now show what is behind them, and every changed pixel (on screen and in the buffer) is one painted through a translucent colour, so Iolo and the avatar change only in their blend pixels; each outline and charmed over poisoned on Iolo; Iolo invisible as a silhouette; Lord British invisible not drawn. The console's `setflag` sets the flags for such tests.
- Verified with before/after windowed shots: Trinsic at dawn, Lord British's castle, a campfire, a container with the paperdoll and a dragged item are pixel-identical to the RGBA renderer; the harpsichord's notes (sprite 24) too, having no translucent pixels; the teleport stars (sprite 7) now tint what is under them blue, where the blend approximation laid a pale haze; a hit rat and Iolo show the outline. CPU per frame: at zoom 1 (1282×802) painting 1.7 ms and uploading 2.3 ms, at zoom 4 0.5 and 0.13 ms (the RGBA renderer queued its draws in 0.6 and 0.25 ms and left the work to the GPU).

### Rendering order (current)

- Mouse picking chooses the object painted last in the most recent frame at the cursor (`PaintStamp`), so clicks agree with what is drawn on top. An object is under the cursor where Exult's `has_point` says so (`ShapeFrame.Covers`): on its frame's opaque pixels, or one pixel past either end of a row of them; items in gumps likewise.
- Paint order is Exult's: each chunk computes paint dependencies between its non-flat objects (and its neighbours') with a port of `Game_object::compare` the first time it is drawn, refreshed whenever an object moves. Flat objects paint first, then each chunk row-major with every object painted after its dependencies (`Game_render::paint_object`). The old single sort key survives only in `FindNearby`'s ordering.
- Sleeping NPCs lie on top of the nearest free bed at bed lift + bed height in the sleep frame (Exult `Sleep_schedule`), unmake the bed on lying down and make it again on getting up.

### Eggs (current)

- Hatchable IREG (shapes 200, 275, 305, 776, 777) parsed as eggs, not containers. 1×1 eggs (200/275) are hidden from paint/pick; moongates (305) still draw.
- Eggs are indexed per chunk with 16 bits per tile (Exult `Chunk_cache::eggs`): solid-area criteria (cached-in, something-on, teleports) mark the whole area, everything else only its perimeter. A step looks up the bits of the tile entered instead of scanning objects within 40 tiles.
- Each step first runs Exult `test_unhatch`/`unhatch` on the tile left: jukebox and sfx eggs clear their hatched flag (auto-reset) or are removed (once), so music no longer re-triggers on every tile inside the area. Once-only eggs of every other type, usecode included, are removed after hatching.
- Teleport-in and map load use Exult `try_all_eggs`: every active egg within 32 tiles except jukebox and teleport, with the dice roll, guarded against recursion so chained teleports stop.
- Implemented: **teleport** (coords or path-egg quality), **usecode** (`event 3`), **jukebox** (plays the track), **button**, **monster** (spawn from IREG data), **missile** (see below), **weather** (Exult `Weather_egg`: data 1's low byte is the weather, its high byte the minutes; see "Weather (current)"). Sfx / voice log a stub once.
- Teleport eggs move the party along (`teleport_party`). A teleport by quality goes to the first path egg of that quality within 256 tiles each way in Exult's `find_nearby` order (before: the first on the whole map, so 14 of Black Gate's 16 such teleporters, Alagner's storeroom among them, went hundreds of tiles off).
- A usecode egg runs its usecode as Exult's `Usecode_egg::hatch_now` does: at once only when `must` (from usecode), otherwise as a script 200 ms later (`usecode fun`, then `remove` for a once-only egg), so two eggs hatched by one step run one after the other. Before, the second call landed on the first's frames waiting for a click and left usecode "running" for good: the Black Gate confrontation (0x608 and 0x6A9 side by side at 2600,2603) stopped after the Guardian's first line.
- Exult `emulate_cache`: when the avatar enters another chunk, the eggs in the chunks that leave the 5×5 round it reset (they can hatch again; a hatched jukebox lets go), temporary things there go, and the scripts not yet started more than 4 chunks off are purged (one that must finish runs to its end). Before, a non-auto-reset egg hatched once for good: Alagner's murder egg (0x6C1) hatched on the first visit, while the story had not come to it, and never again.
- `Game_window::teleport_party` is one place (`U7Game.TeleportParty`), as in Exult: the avatar's walk and barge mode end, the eggs on the tile left let go, the party stands round the new spot, every egg there is tried. Teleport eggs, virtue stones, usecode's `move_object` of the party, the console's `tp` and Shift+click use it. `move_object` of the avatar alone ends its walk and tries the eggs round it; of an NPC, drops its action (Exult `set_action(nullptr)`).
- Missile eggs (type 6, 52 in Black Gate: arrow, lightning and fireball traps) are Exult's `Missile_egg` with its `Missile_launcher` (`CombatEngine.HatchMissileEgg`): the weapon is data 1, the missile its projectile (the fireball 856 if it has none), data 2's low byte a direction 0-7 or 8 for the party, its high byte the delay in std_delays (200 ms). Hatching queues the launcher. A shot in a direction flies as far as the weapon's range from the egg at the egg's height, with no target, and stops at what it runs into (Exult `Find_target`: a flyer one lift high would be blocked there, so the blocking object is hit); a shot at the party goes at a party member it has a straight line to, trying them from a random one on, with no attacker, so nobody fights back. The shots have Exult's default 60 attack points. A launcher stops when its egg is more than 10 tiles off the screen; a party-near or avatar-near egg fires again after its delay while the avatar is within the weapon's range, and is queued again while its chunk is in view (Exult `Missile_egg::paint`). Eggs of other criteria fire once per hatching.
- Verified from `quick`: four lightning traps (weapon 3, at the party every 600 ms) round 520,1031 hatch when the avatar comes into their area and kill Iolo in two seconds (lightning ignores armour); the arrow traps along 2652-2716,1027 (weapon 6, south every 200 ms, three tiles a step) fire into the empty room, hit the avatar standing in their line (18 to 10 hits in 0.6 s) and stop firing when it is 16 tiles away, past the weapon's range of 12.

### Party (current)

- `Actors/PartyManager` ports Exult `Party_manager`: up to 8 members, `add_to_party` (good alignment, in_party and okay_to_take flags) and `remove_from_party` via the usecode intrinsics 0x24/0x25; `get_party_list` returns avatar plus members. `link_party` rebuilds the party from the npc.dat in_party flags at load (NpcDat now keeps the object flags).
- Each avatar step calls `get_followers`/`move_followers`: members walk in Exult's formation (two followers per member, behind-left and behind-right by the 4-way direction) with `Is_step_okay`, `Clear_to_leader`, `Get_cost` and `Take_best_step`. Members in combat, wait or loiter schedules stay put.
- The follow-avatar schedule (`Follow_avatar_schedule` + `Actor::follow`) only acts once the avatar stops: members farther than 6 tiles path to an offset spot beside the avatar; farther than 40 tiles they are brought over like `approach_another`. Teleports (eggs, Home, Shift-click) move the party along (`teleport_party`, free spot within 8 tiles).
- Combat: **C** (or a party member being hit) switches every member and the avatar between the combat and follow-avatar schedules like Exult `toggle_combat`; members fight by their attack mode (see Combat) and drop back to following after five failures to find a foe. A member that dies leaves the party and leaves its body (see Combat); Exult's dead-party list is not kept.
- Not yet: the dead-party list (`Party_manager::update_party_status`), sleeping/paralysed members. The party item intrinsics are in (see "Usecode items (current)"), and so is `resurrect` (see "Usecode scripts (current)").

### Usecode scripts (current)

- `Usecode/UsecodeScript` ports Exult `Usecode_script` (ucsched.cc): the arrays handed to `execute_usecode_array` / `delayed_execute_usecode_array` (intrinsics 0x01/0x02) run against their object over time on 200 ms ticks: cont, reset, repeat/repeat2, delays (ticks, minutes, hours), wait_while_near/far, remove, rise/descend, frame and the NPC frame opcodes 0x61-0x70, next/prev frame, say, step (forced; a barge makes four steps, other objects stay put), face_dir, music, usecode/usecode2 calls, egg, set_egg, hit, resurrect. ### Save / load (current)

- `Game/SaveGame` writes Exult's GAMEDAT layout into `saves/<slot>/`: `U7IREG00..8F` (Exult `write_ireg` / `write_ireg_objects`: plain 10-byte, container 12-byte and egg 12/14-byte entries, extended entries for shape ≥ 1024 or frame ≥ 64, contents terminated by 01, chunks by 00 00), `NPC.DAT` (Exult `Actor::write` layout with the extended magic/mana bytes, readied items marked `02 <spot>`, and `next_schedule` for an NPC walking to its spot), `FLAGINIT` (usecode global flags), `GAMEWIN.DAT` (Exult `gamewin.dat`: day/hour/minute, music track, combat flag; older saves named it `GWIN.DAT` and still load), and `USECODE.DAT` / `USECODE.VAR` (`Usecode/UsecodeDat`, Exult `Usecode_internal::write`: the party in join order, the usecode timers, Exult's saved position; the statics file is empty, as Black Gate's usecode has no statics).
- Loading sets `U7Paths.GameDatOverride` to the slot and reloads the scene, so the normal loaders pick up the saved files; `NpcDat` reads a raw `NPC.DAT` when present (both the original and Exult's magic/mana layouts) and keeps schedule destinations, type flags and the object flags. The party is linked from `USECODE.DAT` in its saved order (Exult `link_party`), or from the in_party flags for saves without that file; the timers go back to the usecode machine.
- NPC schedules on load follow Exult `Actor::restore_schedule`: everyone keeps the place and schedule they were saved with (a loiterer loiters where it stands), an NPC that was walking to its next schedule's spot sets off again (or is put there when far off), and the schedule table takes over at the next period. A new game applies the table at once (Exult `schedule_npcs` after character creation).
- Spawned monsters are saved to `MONSNPCS.DAT` (count + `Actor::write` records) and restored on load. No `schedule.dat`: Exult falls back to the static `SCHEDULE.DAT`, and Black Gate's usecode cannot change schedules (the intrinsics that do, 0xa9 and up, are Exult's own). Spellbooks keep their spells and bookmark in Exult's 18-byte entry (`Spellbook_object::write_ireg`). Not saved: virtue-stone extra bytes. Exult saves are zip files; a `saves/<slot>/` directory with the same files loads, the zip itself does not yet.

### Combat (current)

- Monster eggs hatch via Exult `Monster_egg` packing (`sched`/`align`/`cnt`, shape from d2/d3). NPC-class or `monsters.csv` shapes spawn; others drop a takeable temporary item.
- Spawned stats from `assets/data/monsters.csv` (`Randomize_initial_stat`); health = strength; alignment from the egg unless the egg is neutral.
- Hostility: good↔evil/chaotic, evil↔good/chaotic, chaotic↔evil/good; **neutral never initiates**. Avatar is good.
- Fighting is Exult's `Combat_schedule` (`Actors/Schedules/CombatSchedule`), run like any schedule for monsters (each spawned or saved monster has a schedule brain; an egg's schedule 0 is combat, others loiter, wander, ...), for NPCs pulled into a fight, for party members in combat mode, and for the avatar: Exult runs the avatar's schedule whenever the player isn't walking it, so in combat mode it goes for foes by itself, and a walk of the player's replaces what the schedule was doing.
- A fighter picks a foe among those near the screen (Exult `get_nearby_npcs`, the avatar included) by its attack mode: nearest (preferring foes nobody else attacks, not fleeing), weakest, strongest, random, berserk, protect (attackers of the party member under protection, "On my way!"), defend, flank; manual leaves it to the player. Party members also take on whoever attacks the party or is attacked by it. Monsters get their mode from their kind of fighter at birth (Exult `monster_modes`). It walks within reach with Exult's monster pathfinder (`Approach_actor_action`, stopping when blocked), strikes once 30 dexterity points have built up (Exult `dex_to_attack`), playing the weapon's attack frames (reach, raise, fast or slow swing, one- or two-handed), then the blow lands; with a ranged weapon in range it shoots; blocked from striking, it tries to get adjacent and steps aside. Battle cries and taunts ("To Battle!", "Take this!"). Out of ammunition it swaps to the weapon on its belt or back (Exult `Swap_weapons`), else fights bare-handed.
- It flees when its attack mode says so or below 3 health (unless berserk or it can't die), screaming the first time. After five failures to find or reach a foe it gives up: party members follow again, good NPCs go back to the schedule of the hour (or the one they had), others wander a little. Mages, liches, ghosts and dragons (Exult's `actor_flags`) teleport near their target, summon (the spell's usecode) and turn invisible, with Exult's sprites (stars where they land, sparkles as they vanish); the sounds are not played.
- Getting hit (Exult `fight_back`): a party member hit while in combat mode, or with the avatar unable to act, brings the party into combat mode; an NPC without a target takes on its attacker; one hit by the party may call the guards (see "Guards and arrest (current)"). Exult `set_target` keeps each fighter's target and the numbered NPC attacking it (`oppressor`). The hit actor whose weapon reaches farther steps back a tile (`back_off`).
- Double-click in combat mode attacks anything but party members and bodies (unlocked doors and containers open): the avatar targets it and everyone goes into combat (Exult `double_clicked`). Outside combat mode a double-click uses the thing as usual. The agent console's `use` on an enemy still attacks straight away, and `arena` / `combat [off]` spawn the F3 rats and toggle combat.
- Duel (Exult `Duel_schedule`): the combat schedule play-fighting without damage or music, at an archery target with a bow and a couple of arrows (arrows stick in it, frame by frame), at a fencing dummy or against another duelist with a two-handed sword, breaking off every eighth blow. Verified in Jhelom's fighting school.

- Ranged and thrown weapons (Exult `Combat_schedule::attack_target` + `Projectile_effect`): a bow, crossbow, musket, wand or thrown axe fires a projectile when the target is beyond melee reach (or always, for `uses = ranged`). Ammunition comes from the quiver or any bag (`find_weapon_ammo`), charges from the wand's quality, thrown weapons consume themselves; the missile flies along a straight line at the weapon's missile speed, then rolls to hit with the ranged bonus (+6, minus distance for thrown), applies weapon plus ammo damage with the ammo's damage type and drops the ammo by its drop rule. Archers do not keep their distance (Exult has no such behaviour outside flee mode): they shoot from where they stand and only walk when the target is out of range. `assets/data/ammo.csv` is loaded as `Actors/AmmoTable`. Attacks on tiles are not ported.
- Explosions (Exult `Explosion_effect`, `CombatEngine.Explode`): the explosion sprite of the weapon or missile (Exult's BG list: the powder keg's 4, the burst arrow's 19, ...; else 5) plays where it goes off; a quarter of the way through, the exploding object is removed and everything within half the sprite's width (party included, as in Exult) is attacked with the weapon, the attacker answering for it (the avatar if none). Their sound and powder kegs set off by other explosions (breakable objects) are not ported.
- Missiles are effects, as Exult's `Projectile_effect` is, not objects on the map (`Actors/Missile`, `CombatEngine.Missiles`): a step every 100 ms (`std_delay / 2`, the first one 100 ms after the shot) of as many tiles as the missile speed; it arrives when its path has run out, so a missile whose step ends on the last tile lands on the next step, as in Exult. Its frame is `set_sprite_shape`'s: frames 8-23 by direction for shapes with 24 frames or more, turning by the weapon's rotation speed each step; frame 0 for a one-frame shape only if it is explosive (Black Gate's `volatile_explosive`: the powder keg 704), so the one-frame missiles 70 and 74 are not drawn, as in Exult; others are not drawn either.

### Weather (current)

- `World/Weather.cs` ports Exult's weather effects (effects.cc), which `EffectsManager` keeps on its own time queue: each has a first event a delay after it is made and lasts its game minutes from then (25 standard delays, 5 s, a minute); events run in time order at the times they were due, so long frames catch up step by step. `OnRemoved` stands in for Exult's destructors. How it is drawn: see the bullets after the verification.
  - Storm (2) = the storm, overcast clouds for a minute longer, rain for two more minutes starting gradually 20 ms to 1 s in, and lightning for two minutes less, up to 0.5 s after the rain. Snowstorm (1) = clouds and snow the same way. Sparkle (3, Ambrosia and the generators) = 33 sparkles, numbered 3 and from the egg too, shown indoors. Fog (4) = the clock is foggy from its start to its end, plus 100 sparkles 0.25-1.25 s in. Overcast (5) and clouds (6) are `Clouds_effect`s.
  - `Clouds_effect`: 2-6 clouds (one more half the time when overcast), wind dx, dy of -2..2 px per 100 ms (never both 0), some clouds half as fast again; overcast unless it is weather 6.
  - `Rain_effect`: raindrops, snowflakes or sparkles (Exult's `Basicdrop` frames and steps, `DropKind`), 100 ms steps; a gradual one (the storms') adds 0-4 drops a step up to 200 and takes 0-14 a step in its last 2.5 s (none come back then, a fix, see below).
  - `Lightning_effect`: a 25-50 ms flash, then another after 4-7 s (one time in 50 after 40-280 ms), one at a time, until its time is up (no flash starts past it, a fix, see below). A storm's lightning doesn't flash while the avatar is in a dungeon; usecode's always flashes.
- `EffectsManager.SetWeather` is Exult `Egg_object::set_weather`: 0 minutes means 6000; unless the new weather is fog, all weather goes first if it is sparkles or differs from the current one (`get_weather`: the newest numbered effect), so the same weather again is added alongside; 0 clears it. On every chunk the avatar enters, the weather from eggs 120 or more tiles away ends (`Game_window::emulate_cache`). Only the numbered effect carries the egg, so a storm ends there but its clouds, rain and lightning run their time, Exult's quirk, kept.
- `GameClock` keeps Exult's overcast and fog counts (`set_overcast`, `set_fog`): cloudy while the overcast count is above 0, foggy while the fog count is above 0 between 6:00 and 20:59. Weather is not saved (Exult resets it and the counts on a restore).
- Where it differs from Exult (2026-10-08, the user's pick: Exult's bugs, fixed where its code shows what it meant):
  - Clouds alone (6) leave the overcast count alone. Exult counts it down as they start and never back up, so after any clouds egg, Trinsic's commonest, the next storm isn't overcast.
  - The fog count stays true and the hours apply when it is read. Exult sets it to 0 when a fog starts or ends at night, so a night fog ended by day leaves -1 and cancels the next one; Exult also counts down a fog removed before it started. ### Walking (current)

- Blocking is Exult's `Chunk_cache`: per chunk, tile and lift a count of solid objects with height (`Data/ChunkBlocking`), built per chunk on first use and updated as objects enter, leave or change shape. A wall counts in every chunk its footprint covers (before, walls reaching in from the next chunk east or south were missed). `is_blocked` is ported whole: a walker of its own height (humans 4 lifts) climbs at most one lift, drops at most one, needs headroom, and at lift 0 the terrain keeps walkers out of water and swimmers in it; the multi-tile-step variant serves big monsters. Actors use their type flags (walk, fly, swim, ethereal): npc.dat gets walk on a new game like Exult's `fix_first`, spawned monsters their monster info; saves from before these flags existed are given the same on load.
- Pathfinding is Exult's `Find_path` (`World/Pathfinder`) with `Actor_pathfinder_client`: 3D tiles, every step costs 3, lift changes and closed doors add, swamp doubles, BG cobblestone is cheaper; the open set is Exult's per-cost chains, newest first. There is no node limit: it gives up past a cost ceiling of 3× the estimate, at least three screens wide, so a walk of 200+ tiles is one search (e.g. Trinsic's east gate to 1100,2000). As in Exult, a start estimate of 512 or more (about 250 tiles) finds nothing, and the destination must be at the walker's lift.
- Walks follow Exult `Path_walking_actor_action` (`Actors/PathWalk`): one step per call at the walker's frame time; a blocked step stops the walker and is retried after 0.1-0.6 s up to 3 more times; a closed, unlocked door in the way is opened through its usecode (quality set to 0, as Exult does), walked past and closed behind (Exult's walker is stopped by then, so it hops the last tile past the door: no eggs hatch on it, as in Exult). The tile past the door is figured from the closed door's footprint, as Exult takes it before opening (opening turns a horizontal door's shape into a vertical one; before, the walker hopped to the wrong side). Straight walks (`Zombie`) and A* walks share it. Walking frames follow Exult: the avatar cycles 1,2,1,2 and NPCs 1,0,2,0, diagonal steps use the east/west frames.
- Speeds are Exult's: milliseconds per step, with no run animation. The avatar: by the cursor's distance in a square around it (`Mouse::set_speed_cursor`) slow 400, medium 200, fast 100; in combat 266, with a hostile nearby no fast; keys fast, Shift medium (`Game/WalkSpeed`). Holding the right button, the left on open ground or a key steers a straight walk 8 tiles ahead in that direction, sidestepping a blocked direction (`start_actor_alt`); a double right-click, or a quick left click on open ground, walks an A* path to the tile (`start_actor_along_path`); letting go stops. Idle for 2 s the avatar stands. NPCs: walking to the next schedule spot 200 ms after up to 5 s (A* legs, a straight walk when no path, placed there after 2 failures or 40 legs), loiter 400 ms straight walks within 12 tiles, wander 200 ms A* legs of up to 32 tiles, catching up with the party 100 ms. Formation followers step with the avatar.
- Actors block like everything else (Exult counts every solid shape with height in its chunk cache; NPC and monster shapes are solid). A step onto a tile an actor stands in follows Exult `Actor::is_really_blocked`: the actor in the way steps aside for the walker (`move_aside`: to one side, else diagonally, else they swap places, `swap_positions`), unless it is walking itself, fighting, sitting, kneeling or asleep. The avatar's steering does the same when the way ahead and both sidesteps are blocked (`start_actor_alt`). Persistent walks (Exult's for the avatar and party, e.g. walking to a chair through `set_action_sequence`) plan through NPCs on their feet (`ignore_npcs`) and, blocked by one, plan again up to 30 times. A walker's own tile counts as blocked, as in Exult, so `find_spot` around an NPC finds the tiles beside it.
- Walking to a schedule's spot (Exult `Walk_to_schedule`, `Actors/Schedules/WalkToSchedule`) goes as far as the screen does: with the spot beyond the window enlarged by 6 tiles, a leg ends at its edge (Exult `walk_off_screen`: any tile on that line, `OnecoordPathClient`), unless the spot is near or the NPC has walked 10 legs (the avatar following it); from there, both off the screen, the NPC is put at its spot. - Pace (Exult `Pace_schedule`): back and forth east-west or north-south from its spot, turning about at an obstacle; an actor in the way is told "Step aside!" and asked to move. Verified: Johnson at Trinsic's gate.
- Talk (Exult `Talk_schedule`): Black Gate's usecode (and Iriale's timetable) sets it for an NPC who wants a word: it comes up to the avatar (`Approach_actor_action`), calling "I would have words with thee." if it could reach it (`Fast_pathfinder_client::is_grabable`), and within 5 tiles faces it and starts its conversation. Verified with Iriale.
- Preach (Fellowship podium 697: exhorting with gestures, the seated flock standing to answer "Yea, verily!", a word with one of them, praying at the icon 724; verified with Klog at 21:00), kid games (chasing other children, a quick search; verified in Britain), dance (spins, arm flaps, punches; Chuckles), graze, hound (dogging the avatar), shy (keeping away, the Monster pathfinder client), thief (lifting gold next to the avatar every 8-16 s).
- Crafts: farming (scythe, cutting crops 423 and growing the far ones; Brownie in Britain), mining (pick, ore 915/916 breaking down, gold nuggets and gems turning up), the lab (cauldron, reading, potions on the tables; Rudyom), sewing (bale, spinning wheel, loom, cloth cut and sewn into tops and pants, displayed; Gaye), baking (flour, dough kneaded on the table, oven, bread on the display table; Willy), the forge (blank on the firepit, bellows, anvil and hammer, trough; Menion). Tools come from Exult `Actor::get_attack_frames`, now ported whole (reach, raise, fast or slow swing, one- or two-handed, from the weapon's `actor_frames`); combat strikes use it too.
- Objects in IREG start okay-to-take and container contents inherit their container's flags (Exult `read_ireg_objects`); the temporary flag of 10-byte entries is read back.
- Exult `Schedule_with_objects` (`ScheduleWithObjects`): items made for the NPC's work are removed with the schedule if it still carries them; it walks to a random item of its kind, and puts items down on a table at the edge nearest it (`drop_item`, with the shape `find_spot` on the table top). `Pickup_actor_action` (`PickupAction`) faces the item, bows or reaches up, and takes it, deletes it, or puts it down (optionally temporary); `Face_pos_actor_action` turns to a spot.
- Desk work (Exult `Desk_schedule`): sits at the nearest desk (283, 407) on the chair closest to it; now and then gets up to put desk things (shape 675: quills, documents, inkwells, wax, seals, made for it as needed) on a table, to fetch one lying about, or to stand a moment.
- Waiter (Exult `Waiter_schedule`): sorts the tables within 24 tiles into eating tables (chairs within 3), counters (847) and prep tables (tables, stoves, the cauldron; within 26, 36 or 50); takes the orders of NPCs eating at the inn within 32 tiles, up to four ("What wilt thou have?", "Try the ale.", TEXT.FLX 0x1b-0x1f; to those already eating, Exult's own banter), setting a small temporary plate on the table in front of those without one; cooks at the prep tables (drops a cup or pot there, or works at it with ready/raise frames from a usecode script, stirring the cauldron or stoking the stove); brings each their food in the left hand and sets it on their plate ("Enjoy!", "Specialty of the house!"); waits at the counter, clears plates it set once nobody sits by them, and moves cups, bottles and pots about. Its hands are emptied when the schedule ends. Street maintenance (lamps, shutters) is not ported.
- Dead NPCs and the party get no schedule changes (Exult `find_schedule_change`). An NPC leaving the activity range goes dormant where it is, its action dropped (Exult `Npc_actor::step`), unless it is walking to a schedule's spot, which it is put at (`Walk_to_schedule::im_dormant`); back in range it carries on half a second later (`Npc_actor::paint`). Before, every NPC leaving the range was put at its schedule's spot, which took Brion off his patrol's loiter.
- Schedules run Exult `Usecode_script`s on their NPC through `ScheduleRunner.Script` (face, ready, raise and standing frames with tick delays).
- npc.dat flags follow Exult `Actor::read` bit for bit: the first flag word (asleep, charmed, cursed, in party, paralyzed, poisoned, protection, on a moving barge; dead and temporary only from saves), read/tournament/polymorph in the intelligence byte, Petra in the combat byte, met/no spell casting/zombie, and dead for an NPC below -1/3 of its strength. Exult's two 4-byte flag words are read from saves only: in INITGAME they are garbage. (Before, the garbage was read as flags, so saves made from a new game before this fix carry stray flags, e.g. in `quest4` Spark has bg_dont_move and never walks on its own, and the avatar counts as invisible, so NPCs coming to talk wait; start a new game for clean ones.)
